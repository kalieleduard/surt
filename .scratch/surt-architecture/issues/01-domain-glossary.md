## Question

What are Surt's core concepts, with canonical names and precise boundaries, independent of the physical tables?

It must pin down at least: **Workflow Definition** × **Workflow Run**; **Feature** (the `YYYYMMDD-description` subject) × Workflow Run — can a feature have more than one run (e.g. a re-run after cancellation)?; **Step** × **Step Run** (including child steps generated by foreach/subworkflow); **Execution**; **Iteration** × **Attempt** (brief: iteration = new logical round, attempt = new try after a technical failure) — how do they combine in the Builder↔Reviewer cycle?; **Artifact** × **Artifact Revision** (is a spec edited by the human a new revision?); **Approval** (is it a Step Run of type human approval, an event, or both?); **Agent** × **Agent Profile**; **Task** (is it a core concept or just an artifact the feature workflow interprets?).

Output: `CONTEXT.md` at the root + section C (Domain Model: entities, relationships, invariants) in `docs/architecture/`.

## Answer

Resolved in a grilling session. Full glossary in `CONTEXT.md`; entities, relationships and invariants in `docs/architecture/C-domain-model.md`; trade-off recorded in `docs/adr/0001-task-cycle-as-child-workflow-run.md`.

Decisions:
- **Workflow Definition × Workflow Run:** the run freezes the effective definition at creation and never rereads it; "workflow" alone is avoided.
- **Feature × Workflow Run:** the core knows a **Subject** (a unique name that accumulates runs over time, at most one active); Feature is the Subject of the feature workflow, not a core entity. Re-running after cancelling = a new run of the same Subject.
- **Task:** not part of the core — an item of the Task Agent's manifest, expanded by the for-each.
- **Step × Step Run, children:** each Task runs as a **Child Workflow Run** of `task-cycle` (ADR 0001), not as Step Runs flattened into the feature's run.
- **Execution:** one concrete launch (agent session or Native Operation) of a Step Run; 0..N per Step Run, at most one running; an Approval Gate has zero.
- **Iteration × Attempt:** Iteration = a new logical round triggered by a decision (e.g. a failed review) that creates **new Step Runs**; Attempt = a new Execution of the same Step Run after a technical failure. A finished Step Run is never reopened.
- **Artifact × Artifact Revision:** an immutable Revision with a single origin (one Execution or one human edit); Executions read Revisions fixed at start (Inputs) and produce new ones (Outputs).
- **Approval:** **Approval Gate** (a step that pauses the run) + **Approval** (a recorded decision on a specific Revision); a new Revision does not inherit an Approval.
- **Agent × Agent Profile × Agent Runtime:** role × concrete way of running × adapter (Claude Code, Fake Runtime). "Provider" is reserved for external integrations.
- **Feature workflow roles:** Spec Agent, Task Agent, Builder, Reviewer, Shipper.

Requirement that came up: N approved features must be able to run simultaneously in the same repo — recorded in [Process model and concurrency control](05-process-and-concurrency-model.md).
