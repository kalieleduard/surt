# Map: Surt — Architecture and implementation plan

Labels: wayfinder:map

## Destination

Surt's complete engineering plan — brief deliverables A–L (architecture, Rust workspace, domain, SQLite schema, workflow TOML schema, agent contracts, state machines, artifacts/context, recovery, CLI, roadmap, ADRs) plus the concrete **Milestone 1** proposal — written in the repo under `docs/architecture/`, `docs/adr/` and `CONTEXT.md`, with every decision traceable to a resolved ticket. The map ends when nothing is left to decide before someone can start implementing M1.

## Notes

- **Domain:** a local-first Rust CLI that orchestrates agents (Claude Code CLI) through declarative TOML workflows; SQLite is the source of truth. The original brief is the requirements reference — it is in the first message of the charting session and summarized in the tickets.
- **Skills per session:** `/grilling` + `/domain-modeling` on every grilling ticket; `/codebase-design` on the crate-structure and traits tickets (15); `/research` for research tickets.
- **Incremental plan writing (override of "plan, don't do"):** when resolving a ticket, the session also writes/updates the matching section in `docs/architecture/` (e.g. `D-database.md`), records ADRs in `docs/adr/` when the decision is hard to reverse, surprising and the result of a real trade-off, and updates `CONTEXT.md` as soon as a term is resolved. There is no "assembly" ticket at the end.
- **Grilling style:** every question starts from a real scenario (e.g. "you run `surt feature …`, cancel halfway…"), shows what the user would see under each option (a sketch of `surt status`, a timeline) and the practical consequence; no questions built only from abstract definitions.
- **Language:** plan documents, ADRs, `CONTEXT.md`, tickets, specs, identifiers, SQL and TOML are all in **English**; only the conversation may be in **PT-BR**.
- **Fidelity:** SQL must run in `sqlite3`; TOML must parse; Rust contracts at the signature + invariants level (no bodies).
- **Platforms:** macOS, Linux **and Windows** are MVP targets — every decision about processes, locks, paths, symlinks and worktrees must hold on all three.
- **Permanent constraints from the brief:** the core does not know Spec/Task/Builder/Reviewer/Shipper; no agent-specific tables; a new Claude session per execution; no Builder before human approval; no Task completed without an approved review; no automatic merge into the main branch except the opt-in `[git] merge_into_base = "ff-only"` (fast-forward only — [ADR 0006](../../docs/adr/0006-merge-into-base-is-opt-in-fast-forward.md)); no GitHub dependency.
- **Current crate** (`ferris-says` hello world) is disposable — it will be replaced by M1; the map does not change it.
- **Code rules:** [`rules/`](../../rules/) (architecture, clean code, Rust, SQLite) apply to the plan and to M1; a deliberate deviation is recorded in the rules' `Exceptions:` format, in the doc or ADR that decides it (e.g. [D](../../docs/architecture/D-database.md#rule-exceptions), [ADR 0012](../../docs/adr/0012-agent-runtime-is-the-only-trait.md)).
- **Research:** findings live in `docs/research/<slug>.md` on the disposable branch `research/<slug>`; the ticket points to it.

## Decisions so far

<!-- the index — one line per closed ticket: enough to judge relevance, then zoom the link for the detail the ticket holds -->

- [Claude Code CLI headless capabilities](issues/02-claude-code-cli-headless.md) — every need has a flag, but there is no upfront model/effort validation and no wall-clock timeout, `-p` is not isolated by default (`--bare` requires an API key), and success requires combining exit code + `is_error` + `structured_output`.
- [Cross-platform primitives (macOS, Linux, Windows)](issues/18-cross-platform-primitives.md) — killing a tree requires a process group/Job Object, locking uses a separate file via `File::lock` (Rust ≥1.89), PID identity = start time + boot id, `remove_dir_all` is safe against links but not idempotent; Windows reserved names affect feature names.
- [SQLx + SQLite in practice](issues/03-sqlx-sqlite-in-practice.md) — sqlx 0.9 bundles SQLite 3.46–3.51 (STRICT/RETURNING/JSON ok); it does not enable WAL; `begin()` is DEFERRED (use `BEGIN IMMEDIATE`); concurrent migration is unprotected and the checksum breaks with CRLF; chrono and `CURRENT_TIMESTAMP` timestamps do not compare.
- [Git worktree/merge mechanics and partial states](issues/04-git-worktree-merge-partial-states.md) — git commands are not idempotent (reconcile by reading state); `worktree add -b` is not atomic; worktree-free integration via `merge-tree`+`commit-tree`+`update-ref` is re-runnable (Git ≥2.38); an in-progress merge/rebase is detectable only through markers; `git` CLI > libgit2/gix.
- [Domain glossary](issues/01-domain-glossary.md) — generic core over Subject → Workflow Run (freezes the Definition; ≤1 active per Subject) → Step Run → Execution; each Task is a Child Workflow Run of `task-cycle`; an Iteration creates new Step Runs, an Attempt creates a new Execution; Approval Gate + Approval on an immutable Revision.
- [Process model and concurrency control](issues/05-process-and-concurrency-model.md) — `surt feature`/`plan`/`start` each drive one phase in the foreground and `approve` only records; one Driver per root run guaranteed by a file lock (no lease/heartbeat); Ctrl-C = resumable Interruption; external control only through SQLite; per-project agent slots as lock files; orphans are never adopted.
- [Workflow TOML schema](issues/06-workflow-toml-schema.md) — five `kind`s with no expressions (`agent`, `approval`, `operation`, `loop`, `per_item`); conditions only compare Outcomes; a rejection or a failed review = a new Iteration of a Loop (no `max_iterations`); inputs by name at the latest Revision (ADR 0003, protection at revalidation); explicit `needs`; fixed Item List (`key` + `needs`); the root freezes the closure by SHA-256.
- [Agent contract](issues/07-agent-contract.md) — frozen contracts/profiles; files + validated final JSON; one `.md` per Task alongside the approved manifest; `dontAsk`; no execution timeout.
- [Artifact storage, freezing and revalidation](issues/08-artifact-storage-freezing-revalidation.md) — SHA-256 blobs in SQLite (atomic publication, Approval = id + hash); editable Working Copy only for gated artifacts, edits detected by hash become a human Revision; an approved Revision already read as an Input is pinned and later edits are refused (ADR 0005); per-Execution inputs in `runtime/executions/<id>/`; `.surt/` ignored except `config.toml`/`agents/`; name `YYYYMMDD-<slug>` with a `-N` suffix.
- [Git integration model](issues/09-git-integration-model.md) — a native Operation integrates the reviewed SHA as a merge commit (`merge-tree`/`commit-tree`/`update-ref`, Git ≥2.38) into `surt/<subject>`, re-checking whether the tip moved; Tasks in `surt/task/<subject>/<key>` starting from the tip; Base = `HEAD` at `surt feature`; frozen argv Checks, `failed` skips review; a conflict goes back to the Builder with a full review; read-only Shipper (`title`/`summary`) after `snapshot`; merge into the Base only as opt-in ff-only (ADR 0006/0007).
- [Builder ↔ Reviewer loop state machine](issues/10-builder-reviewer-loop.md) — `blocked` (not final) instead of failure: 3 Attempts and 5 Iterations (no limit on a Loop with a gate), rerunning the command renews the budget; a run only ends `succeeded`/`cancelled` (ADR 0008); dependents of a blocked Task wait; a single profile per agent, no escalation; a Builder with no change makes an empty commit; the Reviewer reads `feedback?`/`conflict?` and always judges the whole SHA.
- [SQLite schema](issues/11-sqlite-schema.md) — 17 singular-named tables (no `step_dependencies`; `execution_input` instead of `execution_artifacts`); UUIDv7 TEXT (recorded exception to the `INTEGER PRIMARY KEY` rule), INTEGER timestamps in Unix seconds written by Rust, `event.seq` rowid without `AUTOINCREMENT`, migration without comments, STRICT, WAL + `synchronous=FULL`; no `deleted_at` — cascading purge (ADR 0009), backup only via `VACUUM INTO`/backup API; content-addressed snapshots; `commit-tree` dated by `step_run.started_at`; rows are born `pending` all at once (run, Iteration, expansion); JSON only where the engine does not decide.
- [Recovery and reconciliation strategy](issues/12-recovery-and-reconciliation.md) — no recovery mode: every driving command reconciles when it takes the lock; an Execution with no recorded end is never accepted; an Intention in a column before every effect (`run_branch` before the branch, new `ref_move` table before moving a ref, pending on the Working Copy); every Attempt starts from a reset worktree with leftovers in a Salvage Ref (ADR 0010); a moved Integration Branch refuses at startup; rate limit/network = Transient Failure that pauses launches without spending an Attempt; never writes to the user's worktree.
- [CLI surface and UX](issues/14-cli-surface-and-ux.md) — 14 commands with `surt stop` (remote Interruption through SQLite); a feature by unique full name, slug or prefix; `surt feature <name>` resumes the spec, a slug with an active run refuses instead of `-2`, `--new-run` restarts the Subject; `approve`/`reject` only record and point to the next command (table in the CLI, not in the TOML); reads never write; exit codes 0/1/2/3 refused/4 blocked/5 cancelled/130; `--json` only on reads; config consolidated in section J.
- [Cleanup, `surt delete` and logs](issues/13-cleanup-delete-and-logs.md) — cleanup runs after the terminal state under the run lock, is idempotent, and stays `pending` (`cleaned_at` column) for the next command if it fails; `succeeded` removes the Working Copy, worktrees, Task Branches and Salvage Refs; `cancelled` removes only the disk and keeps the refs; logs in `.surt/logs/<subject>/` survive until `delete`; an unrecorded edit is never erased (`--new-run` refuses); `delete` refuses an active run, keeps the delivered Integration Branch and does Git/disk → purge.
- [Rust workspace structure and core traits](issues/15-rust-workspace-and-traits.md) — two crates (generic `surt-engine` + `surt` with the CLI and built-in workflows via `Catalog`); the CLI only sees the `Project` facade, whose `drive` does lock → reconcile → advance → cleanup; the only trait is `AgentRuntime` (real store, Git and clock in tests; DIP exception recorded in ADR 0012, with `RunGraph`/`decide()` free of `sqlx` and `git`); store with one method per checkpoint, pure `decide()` scheduler; text-free `Refusal` and `DriveOutcome` map to exit codes; **Run Branch** = the branch of any Workflow Run (ADR 0011/0012).
- [Test strategy](issues/16-test-strategy.md) — Fake Runtime with a typed script in Rust (TOML only for the `surt` binary); fault points at the eight recovery checkpoints + one real `kill` as a smoke test; real Git with three scenarios; CI with fmt, clippy `-D warnings` and the whole suite on all three OSes, real Claude only manually; `test-support` feature (off by default) gates the Fake and fault points; E2E via the binary with a 60 s cap.
- [Capture a real Claude Code stream as a fixture](issues/19-real-claude-code-stream-fixture.md) — F's launcher validated with a real run (subscription, macOS, 2.1.301); `subtype=success` shows up with `is_error=true` on auth/model failure; SIGTERM exits 143 with no `result`; `--json-schema` forces the envelope even on failure (the real gate = files); child environment via allowlist; fixtures in `research/claude-code-cli-headless`.
- [Roadmap + Milestone 1 proposal](issues/17-roadmap-and-milestone-1.md) — M1 = a small Feature end to end with real Claude, surviving `kill -9`; done = suite in CI on the 3 OSes + manual smoke on macOS; 10 commands (no `stop`/`inspect`/`logs`/`restore`/`delete`/`--new-run`/`--json`); Transient Failure blocks instead of pausing; no `ff-only`, `keep`, agent overrides, global config or cross-process slots — nothing requires a migration; slices S1–S6; then M2 operate → M3 no babysitting → M4 tune; v1 = end of M4 ([K](../../docs/architecture/K-roadmap.md), [L](../../docs/architecture/L-decisions.md)).

## Out of scope

- **Graphical interface** — excluded by the brief.
- **Local daemon/supervisor and `--detach`** — to be evaluated later; the process model only needs to not prevent it.
- **External integrations** (GitHub/Linear/Jira) — neither a provider contract nor a reserved column; `external_ref` comes in through an additive migration once there is a provider.
- **A second real AI runtime** (Codex, Gemini CLI etc.) — the trait is designed against Claude Code + Fake Runtime.
- **Overriding/customizing built-in workflows and project-specific workflows** — only `feature` and `task-cycle`, built into the binary; an edge case the schema does not prevent ([Workflow TOML schema](issues/06-workflow-toml-schema.md)).
- **Implementing Milestone 1** — it is the handoff at the end of the map, not part of it.
- **Cancelling or abandoning a single Task, with partial delivery** — in M1 children only end together with the root, and the Shipper only delivers complete Features ([Builder ↔ Reviewer loop state machine](issues/10-builder-reviewer-loop.md)).
- **Coordinating the rate-limit pause across Drivers** (other Features, other projects on the same machine) — v1 pauses only the Driver that hit the limit.
- **Secret redaction, opt-in full logs and log rotation/retention** — v1 only decides where the log lives and when it goes away ([Cleanup, `surt delete` and logs](issues/13-cleanup-delete-and-logs.md)).
- **Removing each Task's worktree as soon as it is integrated** — changes disk usage, not correctness; v1 has a single cleanup at the end of the root run ([Cleanup, `surt delete` and logs](issues/13-cleanup-delete-and-logs.md)).
- **Validation on real Windows beyond CI** (Ctrl+Break on `claude.exe`, `core.longpaths`, junctions) — Windows remains a target; whatever the CI matrix does not catch becomes a bug, not a planning ticket.
- **Cloud infrastructure, microservices, message brokers.**
